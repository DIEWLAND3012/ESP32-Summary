ขา GPIO พิเศษของ ESP32 ที่ต้องจำไปตอบในห้องสอบ

  • ใช้กำหนดโหมดการบูตของชิป (เช่น Flash Mode vs Normal Run)
  • หากต่อวงจรภายนอกดึงแรงดันผิดขณะเปิดเครื่อง ESP32 อาจจะเปิดไม่ติด

ข้อย่อย 1.2

โครงสร้างภายในวงจร GPIO (GPIO Block Diagram Overview)

วงจรภายในของขา GPIO แต่ละขาประกอบด้วยบล็อกสำคัญที่ทำหน้าที่ต่างกัน ดังนี้:

1. Input Buffer & Matrix

รับสัญญาณไฟฟ้าภายนอกเข้ามา มี Schmitt Trigger ช่วยลดสัญญาณรบกวน อ่านค่า 0/1 ผ่าน `GPIO_IN_REG`

2. Output Driver (Push-Pull / Open Drain)

มีทรานซิสเตอร์ PMOS และ NMOS ทำหน้าที่ปล่อยแรงดัน HIGH (3.3V) หรือ LOW (0V) ไปยังภายนอก

3. Internal Pull-Up / Pull-Down

ความต้านทานภายใน (~45 kΩ) ป้องกันสภาวะ "ขาเคว้ง" (Floating Pin) เมื่อยังไม่มีการกดสวิตช์

ข้อย่อย 1.3

โหมดการทำงานของ GPIO ในภาษา C (ESP-IDF / Native Driver)

โหมด (GPIO Mode) คำอธิบาย ตัวอย่างฟังก์ชัน C ที่ใช้
GPIO_MODE_INPUT อ่านค่าจากอุปกรณ์ภายนอก เช่น สวิตช์, เซนเซอร์ดิจิทัล gpio_get_level(GPIO_NUM_4);
GPIO_MODE_OUTPUT ส่งค่าไปควบคุมอุปกรณ์ภายนอก เช่น LED, Relay, Buzzer gpio_set_level(GPIO_NUM_2, 1);
GPIO_MODE_INPUT_OUTPUT ทำหน้าที่ทั้งส่งและอ่านค่ากลับได้ในขาเดียว (เช่น I2C, OneWire) gpio_config(&io_conf);

ข้อย่อย 2.1

FreeRTOS คืออะไร และมีคุณสมบัติเด่นอะไรบ้าง? (ตอบตามเอกสาร)

นิยาม: FreeRTOS คือ ระบบปฏิบัติการเรียลไทม์แบบโอเพ่นซอร์ส (Open-source Real-Time Operating System) ที่ออกแบบมาสำหรับไมโครคอนโทรลเลอร์และระบบฝังตัว (Embedded Systems) ช่วยให้สามารถจัดการหลายงาน (Multitasking) ได้อย่างมีประสิทธิภาพ

8 คุณสมบัติเด่นของ FreeRTOS ในเอกสาร:
  • 1. Multitasking: รองรับการทำงานหลาย Task พร้อมกัน
  • 2. Preemptive Scheduling: แทรก Task สำคัญสูงกว่าได้ทันที
  • 3. Cooperative Scheduling: สลับ Task โดยสมัครใจ ไม่แย่ง CPU
  • 4. Task Priority: กำหนดลำดับความสำคัญของแต่ละ Task ได้
  • 5. Inter-Task Comm: มี Queue, Semaphore, Mutex, Event Group
  • 6. Software Timer: ตั้งเวลาการทำงานของฟังก์ชันได้
  • 7. Low Power Support: จัดการพลังงานอย่างมีประสิทธิภาพ
  • 8. Portability: รองรับหลายชิป (ESP32, STM32, RP2040)
ข้อย่อย 2.2

เปรียบเทียบ Preemptive Scheduling vs Cooperative Scheduling และ Task Priority

Preemptive Scheduling (การขัดจังหวะ)

ระบบ OS จะสอดส่องตลอดเวลา หากมี Task ที่มีความสำคัญ (Priority) สูงกว่าพร้อมทำงาน OS จะ "แย่งขัดจังหวะ (Preempt)" ตัดการทำงานของ Task ปัจจุบันทันที เพื่อให้ Task ที่สำคัญกว่าทำงานก่อน

Cooperative Scheduling (ร่วมมือกัน)

Task ปัจจุบันจะทำงานไปเรื่อยๆ จนกว่าจะ "ยอมปล่อย CPU เอง" (เช่น เรียกคำสั่ง `vTaskDelay` หรือคืนค่าทรัพยากร) Task อื่นถึงจะมีสิทธิ์ขึ้นมาทำงานต่อ

ข้อย่อย 2.3

ถอดรหัสฟังก์ชัน `xTaskCreate` ทั้ง 6 พารามิเตอร์ (ข้อสอบชอบถามมาก!)

xTaskCreate(vTaskFunction, "Task1", 2048, NULL, 1, NULL);
1. pvTaskCode (vTaskFunction) ชื่อฟังก์ชัน C ที่จะให้ Task นี้เข้าไปรัน
2. pcName ("Task1") ชื่อของ Task ข้อความ String ไว้ใช้ Debug
3. usStackDepth (2048) ขนาดหน่วยความจำ Stack (Bytes)
4. pvParameters (NULL) พารามิเตอร์ที่ส่งเข้าฟังก์ชัน (ถ้าไม่มีใส่ NULL)
5. uxPriority (1) ระดับความสำคัญ (ยิ่งตัวเลขมาก ยิ่งสำคัญมาก)
6. pvCreatedTask (NULL) ตัวชี้ตำแหน่งเก็บ Handle (ถ้าไม่ใช้ใส่ NULL)

หมวด 3: ติววิเคราะห์และแก้โค้ดภาษา C (สำหรับคนไม่มีพื้นฐาน)

ปูพื้นฐานไวยากรณ์ C ที่ต้องใช้ + เฉลยแบบฝึกหัดจับผิดโค้ด 2 ข้อ

สรุป 4 กฎเหล็กภาษา C ที่ใช้ใน ESP32

1. เครื่องหมายเซมิโคลอน (;)

ทุกๆ คำสั่ง ต้องปิดท้ายด้วย ; เสมอ หากลืมจะเกิด Compile Error

2. เปรียบเทียบ (==) vs กำหนดค่า (=)

if (x == 5) แปลว่า "ถ้า x เท่ากับ 5"
x = 5; แปลว่า "ให้เอาเลข 5 ไปใส่ในตัวแปร x"

3. วนซ้ำไม่รู้จบ while(1)

ในงาน Microcontroller / RTOS Task ต้องมี while(1) { ... } เพื่อให้โปรแกรมทำงานวนลูปไปตลอด

4. ป้องกัน CPU ค้างด้วย vTaskDelay

ใน FreeRTOS ทุกลูป while(1) **ต้องมี** คำสั่ง delay เพื่อยอมให้ Task อื่นทำงานได้

โจทย์โค้ดข้อที่ 1 โจทย์ให้หาจุดผิดและแก้ให้ถูก

🔴 โค้ดต้นฉบับที่มีจุดผิด (โจทย์จากข้อสอบ):

void vTaskFunction(void *pvParameters) {
    // ผิดจุดที่ 1: ไม่มี while(1) ทำให้ Task ทำงานรอบเดียวแล้วหลุด
    printf("Hello from Task\n");
    // ผิดจุดที่ 2: ลืมใส่ vTaskDelay หรือไม่มี delay ทำให้ Watchdog Reset
}

void app_main() {
    // ผิดจุดที่ 3: สะกดชื่อฟังก์ชันผิด หรือส่ง Parameter ไม่ครบ
    xTaskCreate(vTaskFunction, "Task1", 2048, NULL); // ขาด Priority และ Task Handle!
}
🔍 จุดผิดและการวิเคราะห์ (อธิบายในข้อสอบ):
  1. ขาด ลูป `while(1)` ใน Task Function: Task ของ FreeRTOS ห้ามทำงานจบแล้วคืนค่าออกไปเฉยๆ เพราะจะทำให้เกิดการ Crash หรือ Crash Loop
  2. พารามิเตอร์ของ `xTaskCreate` ไม่ครบ: ฟังก์ชัน `xTaskCreate` ต้องการทั้งหมด **6 พารามิเตอร์** แต่ในโค้ดส่งไปเพียง 4 ตัวเท่านั้น
  3. ไม่มีการเรียก delay คืน CPU: ต้องใส่ `vTaskDelay(...)` ไว้ภายในลูปเพื่อป้องกันไม่ให้ Task ครอง CPU 100% จนระบบค้าง

🟢 โค้ดที่แก้ไขถูกต้องสมบูรณ์ (นำไปเขียนตอบ):

#include <stdio.h>
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

void vTaskFunction(void *pvParameters) {
    while(1) { // 🟢 แก้ไข 1: เพิ่ม while(1) วนลูปไม่รู้จบ
        printf("Hello from Task\n");
        vTaskDelay(1000 / portTICK_PERIOD_MS); // 🟢 แก้ไข 2: เพิ่ม delay 1 วินาที
    }
}

void app_main() {
    // 🟢 แก้ไข 3: ส่งพารามิเตอร์ครบทั้ง 6 ตัว (เติม Priority=1 และ Handle=NULL)
    xTaskCreate(vTaskFunction, "Task1", 2048, NULL, 1, NULL);
}
โจทย์โค้ดข้อที่ 2 โจทย์โปรแกรมอ่านสวิตช์และแสดงผลผิดพลาด

🔴 โค้ดต้นฉบับที่มีจุดผิด:

void app_main() {
    int button_state;
    // ผิดจุดที่ 1: ใช้ = (กำหนดค่า) แทนที่จะเป็น == (เปรียบเทียบ)
    if (button_state = 1) { 
        printf("Button Pressed\n");
    }
    // ผิดจุดที่ 2: ลืมตั้งค่าทิศทาง GPIO เป็น Input/Output ก่อนใช้งาน
    // ผิดจุดที่ 3: ไม่มีลูปทำให้โปรแกรมรันบรรทัดเดียวแล้วจบทำงานทันที
}
🔍 จุดผิดและการวิเคราะห์:
  1. ใช้เครื่องหมายผิด `if (button_state = 1)`: ในภาษา C เครื่องหมาย `=` ตัวเดียวคือการมอบค่า (Assign) ไม่ใช่การเปรียบเทียบ เงื่อนไขนี้จะกลายเป็นจริงเสมอ! ต้องแก้ไขเป็น `==`
  2. ลืมกำหนดโหมด GPIO: ก่อนอ่านหรือสั่งงานขา GPIO ต้องใช้คำสั่งกำหนดทิศทางก่อน (เช่น `gpio_set_direction`)
  3. ขาดลูปในการตรวจจับ: การอ่านสวิตช์ในไมโครคอนโทรลเลอร์ต้องอ่านวนซ้ำตลอดเวลาใน `while(1)`

🟢 โค้ดที่แก้ไขถูกต้องสมบูรณ์:

#include "driver/gpio.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

#define BUTTON_PIN GPIO_NUM_4

void app_main() {
    // 🟢 แก้ไข 1: กำหนดโหมดให้ขา GPIO4 เป็น INPUT
    gpio_reset_pin(BUTTON_PIN);
    gpio_set_direction(BUTTON_PIN, GPIO_MODE_INPUT);

    while(1) { // 🟢 แก้ไข 2: เพิ่มการวนลูปตรวจจับตลอดเวลา
        int button_state = gpio_get_level(BUTTON_PIN);
        
        if (button_state == 1) { // 🟢 แก้ไข 3: เปลี่ยนจาก = เป็น ==
            printf("Button Pressed!\n");
        }
        vTaskDelay(100 / portTICK_PERIOD_MS); // หน่วงเวลาลดสัญญาณรบกวน
    }
}

หมวด 4: การออกแบบ Flowchart ระบบนับคนเข้าห้องน้ำ

ตัวอย่างโจทย์ออกแบบระบบไมโครคอนโทรลเลอร์ตรวจจับทิศทางและนับจำนวนคน

1. แนวคิดและส่วนประกอบของระบบ (Bathroom People Counter)

เซนเซอร์ 2 ตัว (Sensor A & B)

ติดตั้งตรงทางเข้าเรียงต่อกัน เพื่อให้รู้ทิศทาง:

  • เข้า: A ตัดก่อน แล้วตามด้วย B
  • ออก: B ตัดก่อน แล้วตามด้วย A
ตัวแปรนับจำนวน (Count)

ตัวแปรเก็บจำนวนคนในห้องน้ำ:

  • เดินเข้าห้องน้ำ: Count = Count + 1
  • เดินออกจากห้องน้ำ: Count = Count - 1
อุปกรณ์แสดงผล & สถานะ

ป้ายไฟหน้าห้องน้ำ:

  • ถ้า Count > 0: แสดงสถานะ "มีคนอยู่ (Occupied)" / เปิดไฟแดง
  • ถ้า Count == 0: แสดงสถานะ "ว่าง (Vacant)" / เปิดไฟเขียว

2. แผนผัง Flowchart การทำงาน (วาดตามรูปนี้ในข้อสอบ)

3. สรุปข้อความบรรยายการทำงาน (ใช้เขียนบรรยายในข้อสอบ)

ขั้นตอนการทำงานของระบบนับคนเข้าห้องน้ำ:

  1. การเริ่มต้นระบบ (Initialization): ไมโครคอนโทรลเลอร์ตั้งค่าขา GPIO สำหรับรับค่าจากเซนเซอร์ A, B และกำหนดตัวแปร Count = 0 พร้อมเปิดไฟเขียวแสดงสถานะ "ห้องน้ำว่าง"
  2. การตรวจจับคนเข้า (Entrance Detection): เมื่อมีคนเดินเข้า จะบังเซนเซอร์ A ก่อน แล้วตามด้วยเซนเซอร์ B ระบบจะทำการเพิ่มค่า Count = Count + 1
  3. การตรวจจับคนออก (Exit Detection): เมื่อมีคนเดินออกจากห้องน้ำ จะบังเซนเซอร์ B ก่อน แล้วตามด้วยเซนเซอร์ A ระบบจะทำการลดค่า Count = Count - 1
  4. การป้องกันค่าผิดพลาด (Boundary Check): หากค่า Count < 0 ระบบจะทำการปรับค่าให้กลายเป็น 0 เสมอ เพื่อป้องกันจำนวนคนติดลบ
  5. การแสดงผลสถานะ (Output Display):
    • ถ้า Count > 0: แสดงผลหน้าจอ/ไฟแดงว่า **"มีคนอยู่ (Occupied)"**
    • ถ้า Count == 0: แสดงผลหน้าจอ/ไฟเขียวว่า **"ห้องน้ำว่าง (Vacant)"**
